3. Matters Arising / Discussion

3.1 Project Title
The group agreed on the project title "Classroom Booking System," to be hosted at https://github.com/DGKapira/Java-Project-CS350-.git.

3.2 Background
It was noted that classrooms on campus are shared by many lecturers and student groups. While official classes are handled by central timetabling, ad-hoc use of rooms is arranged informally, and there is no shared, up-to-date way to check availability and book a room.

3.3 Problem Statement
The group agreed that students and lecturers often cannot tell which classrooms are free at a given time, causing wasted time, double-booking, and interrupted classes or meetings. It was agreed the system should let users check availability and book with confidence.

3.4 Target Users
The group identified three user groups:
Lecturers — need to find and book a free classroom for extra classes, consultations, or meetings.
Students — need to book rooms for group study, project meetings, or society activities.
Administrators — need to upload timetables and manage classrooms.

3.5 Proposed Solution
It was agreed the group will build a Java application allowing users to search room availability by date/time, view rooms as Available or Occupied, and book a room while the system blocks overlapping bookings. Administrators will upload the official timetable so scheduled lectures show automatically as Occupied. The system will use a database with Users, Classrooms, and Bookings tables.

3.6 Objectives
The following objectives were agreed:
1. Allow users to search classroom availability by date and time range.
2. Display real-time availability status (Available / Occupied).
3. Allow users to book an available classroom.
4. Prevent double-booking of the same room/time.
5. Maintain accurate records of users, classrooms, and bookings.
6. Allow administrators to upload official timetables.

3.7 Scope
It was agreed that the initial scope will include searching, booking/cancelling a single room, and preventing overlapping bookings, plus admin timetable upload. It was agreed that calendar sync, recurring/multi-room bookings, a mobile app, and automatic conflict editing are out of scope for now.

3.8 MVP Features
The group confirmed six MVP features: search by date/time, availability display, booking, double-booking prevention, user accounts, and admin timetable upload.
